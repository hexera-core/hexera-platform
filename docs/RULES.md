# The rulebook

Every decision a mesh run makes on its own is made by a written rule. Each rule has a stable ID,
and each decision the run records in its "why" record names the rule behind it
(`contracts/decision_record.py`). This file is the one home for those rules.

Rulebook version: **56**

How the book is kept honest:

- A rule's ID never changes and is never reused. A rule that stops applying is marked `retired`,
  not deleted.
- **In force** means the code makes this decision today. **Planned** means the ID is reserved
  for a later PR (named in brackets) and no code may cite it yet.
- `tests/unit/hygiene/test_rulebook.py` checks, on every PR, that every rule ID the code cites is
  in force here, that every in-force rule here is cited by the code, and that the version above
  matches `RULES_VERSION` in `contracts/decision_record.py`.
- Changing what a rule decides means changing this book in the same PR and raising the version.

Each decision in the record also says where it came from:

| Source | Meaning |
|---|---|
| `rule` | The code decided by the rule, from measured or declared facts. |
| `user` | The user decided (named an engine, or confirmed one). The rule says why that stands. |
| `ai-lever` | The AI made a judgement call from a declared list (the FEA builder's AI-fea-n), and the rules made it exact inside their limits. |
| `guard-clock` | A guard clock tripped (TIME-3), or one of the clocks still left for the CAD repair work decided (TIME-6). Since D3 no other clock decides anything. |

## ENG: which engine meshes the run

| ID | Status | Rule |
|---|---|---|
| ENG-1 | in force | **Only engines that can take the case are ranked.** An engine is a candidate only if its declared capability covers the flow, the file's form, the number of separate passages and the layers asked for. |
| ENG-2 | in force | **Home turf first.** An engine that declares the measured shape class its home (`EngineSpec.home_classes`: VMTK for tubes and branching passages) comes first, unless its own turf rows mark the case a weak spot or outside. Two home engines rank between themselves by ENG-4. |
| ENG-3 | in force | **The lab record overrides home turf only when it clearly wins:** the challenger has at least 20 runs on at least 8 different shapes of this class, no quality fault, and a 95% lower bound above the home engine's 95% upper bound. A home engine whose own record of 20+ runs here shows a quality fault also loses first place. A home engine never tried on the class keeps it ("home turf unproven"). |
| ENG-4 | in force | **The best lab record on shapes like this one comes first.** The run's geometry is measured, and engines are ranked by the Wilson 95% lower bound of their pass rate on its shape class (`engines/fitness.py`), each run short of 20 counted as a miss, so 7 of 8 never beats 14 of 19. The table is dev-side runs only, versioned (`docs/engines/fitness-changelog.md`). An engine with a quality fault ranks after the sound ones; an engine whose declared turf puts the shape outside is never recommended. Ties go to fewer broken meshes, then fewer bad cells, then the declared turf, layers and ladder order. Time never breaks a tie. |
| ENG-5 | in force | **The fallback ladder walks the same ranking**, after the approved engine, minus the engines already tried and the engines that would refuse the case. With nothing measured, the same rules rank the engines on their record over the whole flow, never a fixed order. |
| ENG-6 | in force | **The user's pick stands.** An engine the user named is never switched on its own; another engine is only offered. A dispute keeps the engine of the mesh it disputes. |
| ENG-7 | in force | **An engine that reads the upload's own format comes first**, measured or not: a conversion loses what the file describes (an ECXML's parts, materials and powers). |
| ENG-8 | in force | **Nothing measured, nothing named: the declared default.** When the run's geometry could not be measured, a run nobody chose an engine for takes the engine the declarations name for its flow (or the flow-only order). |
| ENG-9 | in force | **The user confirmed an engine the measured ranking did not put first** (for example, the ranking was not ready while the user was asked). The confirmed engine stands. This is a gap D1 closes: the proposal should always be the ranked one. |

## SW: whether a run moves to another engine after a failed attempt

Decided by `pipeline/engine_fallback.decide`. The run moves only on measured facts, never on a
review. The order the run moves in is ENG-5.

| ID | Status | Rule |
|---|---|---|
| SW-1 | in force | **Move on: the mesh came out broken** (checkMesh's fatal defects). The next engine in the ladder runs at once. |
| SW-2 | in force | **Move on: the engine could not build a mesh** (it crashed, stopped early or refused the input). |
| SW-3 | in force | **Move on: the same measured failure repeated** on this engine. |
| SW-4 | in force | **Move on: the shared attempts go to the untried engine** when a retry here would leave it no attempt of its own. |
| SW-5 | in force | **Stay: a measured check failed, and this engine's own levers are tried first**, because a retry here still leaves every untried engine an attempt. |
| SW-6 | in force | **Stay: a retry here fits** and still leaves every untried engine an attempt. |
| SW-7 | in force | **Stay: a review never moves the run.** The mesh passed every measured check. |
| SW-8 | in force | **Stay: the engine is not ours to change** (the user named it, or a dispute; see ENG-6). |
| SW-9 | in force | **Stay: another engine cannot change this failure** (the request, the approval or a region split), or the mesh is sound and only short of one of our own bars: its own resolution ladder answers it (LAD-cfd-1), never a switch. |
| SW-10 | in force | **Stay: no untried engine delivers the approved mesh** (same boundaries, units, cell kind and layers). |
| SW-11 | in force | **Stay: the untried engines would refuse** this many separate passages in one job. |
| SW-12 | in force | **Stay: no regular attempt is left.** |
| SW-13 | retired (D3) | **Stay: too little time left** for the next engine's run. Retired: no clock decides a switch any more (TIME-1). A next engine that runs past the run's guards is a guard trip (TIME-3). |
| SW-14 | in force | **Stay: the fallback ladder is switched off** by a setting. |
| SW-15 | in force | **No decision: the last attempt did not fail.** |
| SW-16 | in force | **Move on, to another kind of mesh: the system's own pick made no mesh, or a broken one** (a time-out, a crash, a stop before meshing, broken cells), and no untried engine delivers the same kind. The next engine in the ranking takes the run when the only differences are the mesh's file format and cell type: never fewer layers, a worse wall fit, a lost requirement or a setting. The user is told what changes, as it happens and beside the delivered mesh. Never for an engine the user named (ENG-6). |

## DEL: which valid mesh a run delivers

When a run built more than one valid mesh, `application/review_delivery.rank_key` ranks them by a
fixed order of measured facts. The first fact that separates the winner from the runner-up is the
rule. An invalid mesh is never delivered.

| ID | Status | Rule |
|---|---|---|
| DEL-0 | in force | **The only valid mesh** the run built is the one delivered. |
| DEL-1 | in force | **A mesh the review confirmed is the wrong problem ranks last** (a cited, inspected wrong-problem finding, not a concern). Shadow period only: once `VERDICT_BY_LIMITS` is on, a review ranks nothing and this position never separates two meshes. |
| DEL-2 | in force | **A mesh that passes every fixed quality limit beats one that does not.** |
| DEL-3 | in force | **Fewer failed quality checks wins.** |
| DEL-4 | in force | **Meeting more of the approved plan wins** (layers on the wall, wake refinement, stated sizes). |
| DEL-5 | in force | **Better worst cells win**, compared to the whole degree of non-orthogonality. |
| DEL-6 | in force | **On a measured tie, the mesh whose review passed wins.** Shadow period only: once `VERDICT_BY_LIMITS` is on, a review ranks nothing and a tie on everything measured goes to the earlier attempt (DEL-10). |
| DEL-7 | in force | **Lower worst non-orthogonality wins** (exact value). |
| DEL-8 | in force | **Lower worst skewness wins.** |
| DEL-9 | in force | **More wall covered by prism layers wins.** |
| DEL-10 | in force | **The earlier attempt wins** when everything measured is the same. |

## VER: pass, delivered with concerns, or fail

Decided by `contracts/decision_record.verdict` from measured numbers alone, read off the delivered
mesh by `engines/verdict_limits.py`. Every finished run's why record carries one `verdict` entry:
the outcome, the VER rule, and every row below with its measured number, its limit and its
source, so the verdict replays from the record. Nothing the AI reviewer wrote is an input.

**The AI reviewer only adds notes.** It still looks at the pictures. Its points are shown to the
customer under "Reviewer notes", each one labelled "Reviewer note". It cannot change a status,
start a rebuild, a bonus attempt or a retry, rank one mesh over another, or fail a job as the
wrong problem. A user's own dispute ("rebuild it") is the user's decision and still rebuilds.

**Shadow first.** The setting `VERDICT_BY_LIMITS` (off by default) switches the limits verdict on.
While it is off, the review-led verdict still decides, and the limits verdict is worked out on
every run beside it: one `verdict shadow:` log line (limits outcome, rule, review-led outcome,
whether they agree, the limits missed) and the `verdict` entry in the why record.

**On for dev.** The deploy target turns it on for shared dev and every personal environment
(`verdict_by_limits` in `.github/workflows/deploy.yml`, sent to the workers as template metadata,
so a fleet deploy applies it). Prod keeps the default until dev has run with it.

| ID | Status | Rule |
|---|---|---|
| VER-1 | in force | **Fail: no valid mesh.** The executor's gates refused the last attempt, or the mesh's own numbers fail one of the engine's gating rows (its `criteria.py` rows marked gating: checkMesh fatal defects, wall captured, ports captured, the quality floors, regions and interfaces). An invalid mesh is never delivered. The resolution floor, the share of skewed faces and the one-job cell limit are not validity: on a sound mesh they are notes (LAD-cfd-3, LAD-cfd-4). |
| VER-2 | in force | **Delivered with concerns:** the mesh is valid but misses at least one production limit (table below). Each one is listed as measured vs limit. |
| VER-3 | in force | **Clean pass:** valid, and every production limit that applies is met (a limit whose number was not measured is listed as unmeasured and decides nothing). |
| VER-4 | in force | **Wrong problem, by measured checks only.** The run failed at a gate that measures one of the ways a mesh can be a different problem than the one confirmed (table below). The gate's own measured account is what the user reads. |
| VER-5 | in force | **A review never reruns or fails a run once the limits decide.** When a mesh passed every gate, its review ends the run whatever it said, and also when it did not conclude (the model was busy, down, or gave no answer). No review rerun, no rebuild, no failure: the measured limits decide. A crash after the review is rescued the same way, whatever the review said. A user's own dispute keeps its routing. |
| VER-6 | in force | **The recorded review verdict is the measured one once the limits decide.** A review that ran on a mesh every gate passed records PASS (job row and final result) when the measured limits deliver it, pass or pass with notes. The model's own call is kept beside its notes, labelled. Job fb44fed7 recorded the model's FAIL on a valid FEA mesh. |
| VER-7 | in force | **A reviewer point a measurement settles is not an open point.** When a review axis is about a property a measured row measures exactly (layer coverage, cell quality, regions, interfaces, passage resolution, FEA element validity and detail, the FEA face accounting), and that row was measured and met, the point is kept with the measurement that settles it, and is not shown as a note to act on. A point no measurement speaks to stays a note. |

### VER-2 production limits, per engine and purpose

| Limit | Engines | Applies to | Limit value | Source |
|---|---|---|---|---|
| Worst face non-orthogonality | snappy, cfMesh, multi-region | every flow | at most 70 degrees | checkMesh warns above 70 |
| Worst face non-orthogonality | gmsh | external and internal flow (not FEA) | at most 85 degrees | gmsh's own gating bar, so a mesh past it never validates |
| Share of skewed faces | snappy, cfMesh | every flow | at most 0.05% | checkMesh's skewness bars as a share of all faces; a production limit on a sound mesh, never a validity bar (cfMesh often does not report it) |
| Wall covered by prism layers | snappy, cfMesh, multi-region, VMTK | when the approved plan builds layers | at least 80% | lab history: below it wall shear and y+ are unreliable on a material share of the wall |
| Layers built short of the layers asked | cfMesh | when the approved plan builds layers | none short | the layer census (layers in the meshDict vs the request) |
| Connected cell regions | snappy, cfMesh, gmsh, VMTK | every flow | at most 1 | checkMesh's region count: a second region is cut off from the flow |
| Cells across the narrowest passage | snappy, cfMesh, gmsh, VMTK | internal flow | at least the resolution floor (12) | the resolution floor's own reading; narrow side passages it set aside are listed here |
| Stated requirements met | every engine | every flow | no near-miss | the executor's measured requirement checks (`requirement_caveats`) |
| A believable size for what it is | every engine | every flow | no size concern | the unit-plausibility check on the delivered body |
| The engine's own declared advisory lists | snap-grid | every flow | empty | `engines/snapgrid/criteria.py` (thin layers short, resolution short) |
| Worst scaled Jacobian, over the whole curved element | every FEA adapter (gmsh today) | a mesh built from an FEA plan | at least 0.2 for straight (4-node) tetrahedra; at least 0.01 for curved (10-node) ones | Cubit/Verdict's acceptable range for straight tetrahedra. A curved element's figure reads its curving as well as its shape, and none of the version-1 solvers checks it (they check validity), so a curved mesh is noted only under 0.01 (Areen, 22 Oct) |
| Worst Jacobian ratio across an element's nodes | every FEA adapter | a mesh built from an FEA plan | at most 30 | Ansys MAPDL's corner-node warning |
| Worst aspect ratio (1 is a perfect element) | every FEA adapter | a mesh built from an FEA plan | at most 20 | Ansys MAPDL's aspect-ratio warning |
| Angles between the faces of an element | every FEA adapter | a mesh built from an FEA plan | between 5 and 170 degrees | Hexera's internal gate (design section 9) |
| Mesh zones short of the FEA plan's rules | every FEA adapter | a mesh built from an FEA plan | none | `engines/fea_checks.py`: elements per quarter-turn and through the wall at each hot spot |

The FEA rows are the strictest limit among the version-1 solvers (Abaqus/CalculiX, Nastran, Ansys;
`engines/fea_quality.LIMITS`, read by `engines/verdict_limits.fea_limits`), measured on the solver's
own element (`engines/fea_quality.py`). For an FEA mesh, VER-1 also refuses any inverted element
(a Jacobian not above zero anywhere in the curved element) and any degenerate one: a VALID MESH is the only thing that fails an FEA run (Areen, 21 Oct). The rows above, the quality note floor (SICN 0.1 for straight elements, 0.01 for curved ones) and the elements through each wall are notes on the delivery, never a failure.

The table is `engines/verdict_limits.PRODUCTION_LIMITS`. A limit names engines and flows, never a
file, a part or a model. Changing a number here means changing the table, this book and the
version in the same PR.

## TIME: planned work decides, the clock only guards

A run must come out the same on a quiet machine and on a busy one. So **planned work** decides
what a run does: cells, iterations, triangles, samples, ladder steps and attempts. These are the
same on every machine. A clock is kept only as a **guard**, so a hung step cannot hold a machine
forever. The numbers live in `contracts/work_limits.py`. Every guard's planned work and size goes
into the run's why record as a `work_limit` entry, and every trip as a `guard` entry. Both replay
from their recorded inputs.

| ID | Status | Rule |
|---|---|---|
| TIME-1 | in force | **Planned work decides, never the clock.** A step runs its planned work to the end. Whether a step or a ladder rung runs, how coarse a pass is, which engine runs next and what the verdict is never depend on how long anything took. |
| TIME-2 | in force | **Each guard is 3 times the planned time.** Planned time is the planned work divided by the step's slow rate (the 10th percentile the lab measured: snappy 1,500, cfMesh 1,200, VMTK 4,000 cells a second). A guard is never shorter than the step's fixed cap before D3, so nothing that finished before is cut now. It is never longer than the ceiling the job around it allows. An engine with no lab rate keeps its old cap. A run watched for progress (RUN-5: snappy, cfMesh, VMTK, multi-region snappy, gmsh, snap-grid) has its machine's wall as its guard, and inside it is stopped only when it makes no progress for the stall window; that stop is a guard trip too. |
| TIME-3 | in force | **A guard that trips is an infrastructure failure.** The attempt ends and nothing on disk is judged. The same attempt is run again once, unchanged. A second trip ends the run as "ran out of time". A trip never picks a lever, skips a step, makes a pass coarser, picks or switches an engine, or changes a verdict. The one exception is TIME-8: a trip once the attempt already holds a valid mesh keeps that mesh. |
| TIME-4 | in force | **A wait that feeds a decision waits for the answer.** This covers the measured engine order, the intake's recommendation and the geometry check's naming. Their guards are long (15, 5 and 9 minutes). A trip counts as that step failing, the same path as any error in it. It is never a different answer chosen because time ran out. |
| TIME-5 | in force | **The job's own clocks are guards only.** These are the builder's 3,600 s per attempt and 9,000 s in total, the pipeline's 21,600 s, the reviewer's 1,800 s and the Cloud Run task's 4 hours. A trip ends the attempt or the run as ours ("ran out of time"). The builder's and the pipeline's trips are recorded as guard trips; the reviewer's ends the review as one that did not conclude (our failure, never a verdict). (The snappy planner's 1,800 s setting is read by nothing.) |
| TIME-6 | in force | **The CAD repair steps still decide by the clock: inspection (25 s) and repair (120 s).** If inspection runs out, the repair status is "inconclusive". If repair runs out, the original file is meshed. These steps belong to the repair work (#201). They are recorded as `time_limited` with source `guard-clock`, and they are left for that work to bound by face count. |
| TIME-7 | in force | **A repair step on a finished mesh is planned work too.** The cfMesh rescue's optimiser (`improveMeshQuality`) runs a number of loops planned from the mesh's cells: 40 million cell-loops in all, never more than 20 loops and never fewer than 10 (cfMesh's own default). So a 2 M cell mesh gets 20 loops and a 4 M cell mesh 10; the rescue asked 50 before, whatever the mesh. On 8 dev-side meshes (29 Oct), 6 untangled in 2 or 3 loops (50-140 s), and on the 2 tangled ones the bad faces stalled at 3-19 from loop 2-5 while each loop cost more (1.4 M cells: 498 s for 20 loops, 1,263 s for 29). It also stops itself, read from its own count, when it is not untangling: at its 3rd untangling loop its bad faces are still at least a tenth of its 1st loop's, and at least 1,000 (on every dev-side mesh it untangled, loop 3 was under 3% of loop 1; the benchmark's microfluidics spiral read 52,518, 35,250, 52,544, at 6 minutes a loop). What it left is not kept, and the rescue goes on with the best mesh measured so far. Its guard is 3 times that work at its slow rate (5,000 cell-loops a second: a loop's cost follows the tangled region); the protective re-mesh is guarded like a cfMesh run of the same cells; neither guard is ever past what is left of the run's. Before (full benchmark, 29 Oct), the optimiser ran its 50 loops whatever the mesh, under the run's 4-hour guard: on tangled 2.5-4 M cell meshes it ran 2.5 to 3.7 hours and tripped, and 4 files main delivered came back as "ran out of time". The numbers were set on dev-side files only. |
| TIME-8 | in force | **A trip never throws a valid mesh away.** When a guard trips after the attempt already holds a valid mesh, that mesh is kept, with a note, and the attempt goes on to its checks as usual. It is never replayed or ended as "ran out of time". Valid means measured with no fatal defect: in the cfMesh rescue, the mesh as built or a better candidate measured before the step that tripped; in snappy, an earlier pass's sound mesh kept aside; for the passage flow reading and the passage measure, the mesh they read (which is checked without the reading, as before the reading existed). That reading is never taken beside a mesh with a fatal defect, which fails its gate whatever the flow does. With nothing valid in hand, TIME-3 holds. The trip is still recorded (rule TIME-8, with what was kept), so the run's record shows the guard fired. |

### The interface for any driver (FEA step 4 included)

```python
from meshpipeline.contracts.work_limits import PlannedWork, guard_for
from meshpipeline.engines.determinism import note_guard_trip

work = guard_for("snappy", cells=planned_cells)       # or PlannedWork(where="fea.gmsh",
                                                      #   unit="elements", amount=n, rate=r,
                                                      #   floor_s=..., ceiling_s=...)
run(..., timeout=work.guard_seconds)                  # the only clock
if timed_out:
    note_guard_trip(work.where, workspace=ws, **work.as_dict())   # the executor ends the
                                                                  # attempt; the graph replays it
```

## PLAN-cfd: the flow mesh's sizing, on every flow engine

The sizing rules every flow engine (snappyHexMesh, cfMesh, VMTK, gmsh) follows for a CFD mesh,
from the part's own measured passages - never from a file or a part name
(`engines/resolution_policy.py`, `engines/gap_sizing.py`).

| ID | Status | Rule |
|---|---|---|
| PLAN-cfd-1 | in force | **Cells from the measured narrowest gap, locally.** Every passage the flow goes through gets at least 13 cells across its own width, refined only where it is narrow: snappyHexMesh and cfMesh refine boxes and distance bands round the narrow spots of the staged wall (`engines/gap_sizing`, the cost checked against the cell limit before meshing); VMTK sizes every edge from the local radius (2 / `edge_length_factor` across); gmsh sizes from the local radius field. The plan is written beside the case (`gap_sizing.json`) and cited in the why record. |
| PLAN-cfd-2 | in force | **Every opening, at least 8 cells across its own width.** A port narrower than 8 wall cells gets its own finer cells at the port only (snappyHexMesh: the port's refinement level; cfMesh: a local refinement on the port's surface). Under about 4 the octree seals a port over and it comes back with no faces. |
| PLAN-cfd-3 | in force | **The big-machine hook.** When the cells the sizing rule needs are over one job's cell limit, the plan records `route_big` (and the why record cites it). The big-machine runner is not built yet: until it is, the run is meshed as the limit holds, and the delivered note says so in plain numbers (the cells the full rule needs against the one-job limit). |
| PLAN-cfd-4 | in force | **A size the user asks for on a part becomes that part's own level (snappyHexMesh)** (`engines/snappy/part_levels.py`). On a surface of several named parts, the notes are tied to the parts by NOTE-4 (the reading the user checked before approval first, NOTE-5). A size becomes a level against the background cell the dict really uses: the coarsest level whose cell (base / 2^level) lies inside the user's range, else round(log2(base / size)) at the range's middle; "finer" is one level over the surface's own, "coarser" one under. A part that is its own region in the staged surface gets its level there (finer or coarser). A part merged into one wall with others is refined near its own surface (a distance region on its own file, 3 cells deep) and cannot be made coarser: that is said, not applied. What the notes asked and what each part got is said once per run (in cell sizes, not levels) and kept in the why record. Unclear words, one part, or no answer: nothing applied - never a failed run. |

## LAD-cfd: the resolution ladder, and what a sound mesh becomes

A mesh is SOUND when every blocking gate passed and the trial solve converged: no fatal checkMesh
defect, no negative volume, every port with faces, the right region, the domain asked for. The
resolution floor (12 cells across the narrowest 5% of the wall), the share of skewed faces and the
one-job cell limit are our own bars, not validity: on a sound mesh they are notes, declared as
non-blocking gates (`GateSpec.blocking=False`). `engines/resolution_policy.py` holds the rules.

| ID | Status | Rule |
|---|---|---|
| LAD-cfd-1 | in force | **The ladder's next rung, never an identical re-run.** A sound mesh short of the resolution floor sends the next attempt up one rung on the same engine: the cells-across target at the narrow spots is multiplied by 1.5 (rung 1), then 2 (rung 2), or by what the measured shortfall needs ((floor + 1) / measured) when that is more, never past 3. snappyHexMesh also refines where the mesh measured short (its narrow retry); cfMesh detects and sizes its narrow-spot boxes that much finer; VMTK divides its edge factor by it, and its budget fit may coarsen the edge back only to the rung's own cells across (a rung that cannot fit one job is not started, and the sound mesh stands); gmsh sizes its passage field by it. The rung is written into the attempt's workspace (`resolution_ladder.json`), so the case the mesher gets is never the one it already ran (the rerun guard hashes it). No rung when there is no room left to refine: the mesh already has 90% of the cell limit, or the attempt's gap plan was already held by the limit (`limited`, `over_limit`, `accepted_fewer`) with its budget the whole one-job limit - the next plan has the same cells to share and shares them the same way (lab: 7 of 7 such rungs rebuilt the same mesh). A held plan under a smaller budget keeps its rung: the next plan may raise the budget. |
| LAD-cfd-2 | in force | **A switch does not spend the ladder.** When the run moved to another engine and that engine's first mesh is sound but short of the floor, it still gets one rung - inside the run's ceiling of 3 attempts. The time left never decides it (TIME-1, since D3): the run's deadlines are guards only (TIME-5), and a rung that runs past them is a guard trip (TIME-3); the earlier sound mesh is still delivered (LAD-cfd-3). |
| LAD-cfd-3 | in force | **Ladder spent, mesh sound: delivered with a note.** The note names the narrowest gap, where it is, its cells across and the floor ("the gap at (x, y, z) has 8 cells across; 12 is our floor"). The share of skewed faces is a production limit (VER-2), not a failure. And a later attempt that comes out broken never throws an earlier sound mesh away: the run delivers its best sound mesh instead of the failure (`node_deliver_sound`). The best is the one with the most cells across its narrowest gap (one that meets the floor beats any that does not), the newest on a tie; and when the last attempt is sound but a rung left it coarser than an earlier sound mesh, the earlier one is delivered too. The same holds between snappyHexMesh's own passes: a sound pass is kept aside while the next pass tries for a cleaner one, and put back if that pass comes out broken. |
| LAD-cfd-4 | in force | **Over one job's cell limit is a note, never a retry.** A sound mesh bigger than one standard job is delivered at the size its sizing rules asked for, with the note; a retry could only shrink it. The worker's trial solve is not run on it (its matrix outgrows the worker); checkMesh's fatal topology and a lean count of the mesh's connected regions (from its cell graph; one per passage meshed) stand in, and a disconnected pocket still blocks. |

## INS: the fluid's inside (where the fluid is, how it gets in and out)

One map per part drives every step below, so the steps cannot disagree (`cad/inside_space.py`).
The stage's openings, the stage's question, the staging's seals and seed, and the checks before
meshing all read it. Nothing here reads a file name, and no model decides any of it.

| ID | Status | Rule |
|---|---|---|
| INS-1 | in force | **The inside-space map.** The part's surface is drawn on a grid of at most 6,000,000 cubes (400 a triangle, never fewer than 1,500,000; a cube never finer than 1/5,000 of the part's diagonal). Every loop of the surface that could edge an opening - an open rim, or the outline of a smooth patch no face lies across - gets a cap, and the free cubes are flooded from the grid's border. A **pocket** is space the open air reached with no cap but reaches now only through caps; space no flood reaches even without caps is a closed shell's inside (the metal, or a body that is the fluid). A cap with open air on one side and a pocket on the other is a **mouth**. A cap with a pocket on both sides (a step in a bore, a barb's ridge) is taken away and the space flooded again, until none is left. A cap whose pocket runs less than 1/10 of the cap's width behind it (under 9 in 10 of its points) closes a dent in the outside and is taken away too. Of two mouth caps of one pocket that share most cubes, the tighter loop is the mouth; of two facing one way on one axis, one just behind the other (within its width, at about its size, or within two cubes at any size), the one in front is. Pockets lined on the same side by one piece of the surface cut along the mouths (at least 1/4 of each one's lining) are one pocket. A pocket holding at least 5% of the largest one's space is a **passage**; a smaller one is a side pocket. Surfaces of more than 2,000,000 triangles are not mapped (the shape rules stand). |
| INS-2 | in force | **Openings are the mouths.** Every mouth of a passage is an opening, of any shape or size; a mouth of a side pocket (a bolt hole, a blind dimple) is shown as not an opening, for the user to click. A loop too small for the grid (under 4 cubes across) is read by the hole finder's shape rules (`cad/open_ends`), so no small opening is dropped - unless the map reads the space ahead of it as the part's own inside (a port from a tube into the chamber round it). The STL upload, the stage's click and the staging read this one definition (`open_ends.find_holes`). A CAD part's face-read openings whose outside is the part's own inside (a step in the bore) are proposed as not openings, and a CAD part whose faces give fewer than two gets the map's mouths. When the map's openings differ from the shape rules' and only the shape rules' close the fluid in, the shape rules' are proposed, with a note. |
| INS-3 | in force | **The flow kind by rule.** The user says the fluid flows through the part: when the map finds a passage with two mouths or more, or two openings are confirmed (a body that is the fluid, with its lids), it is internal flow. When it finds neither, the stage asks one plain question - "This part has no openings or inside for fluid. Did you mean flow around it?" (or, for an inside with one mouth, that the fluid has no way through it) - with flowing around it the one-click way out. Never a job that can only fail. A part the map could not read is never asked (the intake asks). |
| INS-4 | in force | **The point inside the flow is the deepest point of the passage**: the cube farthest from every wall and cap (the first in grid order on a tie) of the passage most confirmed openings open, taken when the closed boundary's winding number there is one, at least 4 of 6 rays cross it an odd number of times, and it stands at least 2% of the smallest opening's radius from every face. For a body that is the fluid, the deepest point inside it. Otherwise the point is stepped in from an opening, as before. Never a model's guess, never a point in a wall. |
| INS-5 | in force | **Caps fit each mouth's own loop; nothing leaks.** Every mouth no confirmed opening claims is sealed into the wall before the fluid's side is read (a mouth just behind a confirmed opening, inside its footprint and no wider, is that opening's own throat and stays open). When the loop-by-loop vote cannot settle which side is the fluid's, the pieces that line the passage are the fluid's. When the map's own seals leave the boundary unclosable, the same openings are staged once more as the shape rules alone read the surface, kept only if that closes, and recorded. A cap is the lid of the loop's own points (flat, or pulled toward the smallest area when the loop is not flat); a ring-shaped mouth (a centre body in it) is stitched round its centre, or, when a loop does not turn once round the centre, joined to the outer loop by one bridge and clipped whole. Then the sealed check: every edge of the fluid boundary on exactly two faces, and a flood of the boundary from the point inside the flow stays inside it. A leak is located and named. A wide one - no thickening of the wall by up to four cubes closes it, so any mesher would fill the outside too - on a boundary that is open or crossed by its own lids stops the staging before meshing; a narrower gap (a mesher's own cells close it), or any leak of a closed, uncrossed boundary (a grid artefact at a gap finer than its cubes), is recorded only. The file is never patched: a gap that is not an opening, and that the user did not ask to close for the mesh (INS-8), is named as a CAD defect ("this needs CAD repair") for the CAD repair stage. A passage the confirmed openings do not close is refused with the place of the opening left open. |
| INS-6 | in force | **Every confirmed opening is its own patch.** Each one comes out of the staging as a patch with faces on the closed fluid boundary, or the staging stops before meshing and names it. |
| INS-7 | in force | **A broken surface is said, never healed.** The check counts the drawn surface's open edges that edge no opening (an open pipe end is an opening; a tear is not) and its loose pieces (each holding at least 1/200 of the skin); a CAD solid's B-rep is closed, so its skin's unwelded seams are not counted. When the user says the fluid flows through a part with no way through, and its surface is open or in loose pieces, the stage does not ask about flow around it: it says the part needs CAD repair first, and what it found. Nothing here changes the file - no gap is closed in it, no piece joined, no face turned, no wrap: that is the CAD repair stage's work. Leaks narrow enough to close for the mesh alone are INS-8's proposal, not this stop. |
| INS-8 | in force | **Leaks up to a size the user confirms are closed for the mesh, never in the file** (Fluent's "close leaks up to X"; `cad/inside_space.read_leaks`, `cad/internal_surface._close_leaks`). A triangle surface whose map as drawn finds no way through it, and that is open (an edge on one face, or a second piece), is read again with its leaks closed: the wall is thickened by r cubes (r = 1, 2, 3, 4 in turn; a gap up to 2r cubes across closes) only within r + 1 cubes of an edge not on two faces or of where two pieces of the surface meet - never anywhere else, so a narrow channel of a closed surface is never taken for a leak. The first r that finds a passage with two mouths - or, for a body that is the fluid, the inside of its closed shell, when the map as drawn read no pocket at all and the inside regained holds at least 5% of the part's box - is the reading, when every leak it closed is narrower than that inside (one as wide as the passage is a missing piece, not a leak); else the map as drawn stands. A **leak** is a piece of the closed cubes (outside the caps left standing) between a passage and space that is not it - the open air, the part's material, another pocket; its width is the widest way through it, twice the clearance from the drawn surface that every step of that way keeps, and its place is where that way is narrowest. The openings are that reading's mouths, and every hole too small for the grid to see (under 4 cubes across) is a leak of that reading, listed with its own size, not an opening: the inside was found only once gaps of that scale were closed (a small real port is the user's to click). The stage lists every leak (the widest first, up to 20, with width and place) and proposes one switch, on by default: close every leak up to the widest found plus one cube, at two figures, rounded up; the user can change the size or switch it off (then the surface is meshed as drawn, and a leak it cannot mesh across stops the staging, named). The confirmed size goes with the run to every route's staging (`leak_closing.json` beside the run's surface): the map is read with every gap up to that size closed (r = size / two cubes, at most 6), a leak at a loop the staging seals anyway (a pinhole's rim) or at a confirmed opening is the seal's or the opening's, and only when the flood from the point inside the flow still gets out does each other leak get a **cover** in the wall - the faces of its closed cubes the passage touches, its rim laid on the drawn surface and its inside smoothed - before the flood is tried again. The why record names every leak, its width, place and what closed it, and says the uploaded file is unchanged. |

## PLAN-fea: the FEA meshing plan

A structural solid (purpose Structural / FEA, 3D, no face named by the user) is meshed by the
deterministic FEA driver (`engines/fea_*.py`), not the builder loop. The plan is computed from the part's
measurements (FEA build step 3: walls, hot spots, bodies) and is the same for every engine; each
engine is one adapter that meshes it (gmsh first, `engines/gmsh/fea_adapter.py`). The plan is
written to `fea_plan.json` beside the mesh, with these sentences in plain words. No model is asked
anything: AI changes to the plan are off (Areen's decision 4, 20 Oct).

| ID | Status | Rule |
|---|---|---|
| PLAN-fea-1 | in force | **Quadratic tetrahedra, solid only.** Version 1 meshes the solid with 10-node tetrahedra; thin walls are meshed as solid too (shells are version 1.1). |
| PLAN-fea-2 | retired | **The detail level set the element count** (Quick / Standard / Fine). Retired 21 Oct: one rules-based plan, sized by PLAN-fea-14 and held under the element limit by PLAN-fea-8. |
| PLAN-fea-3 | in force | **At least 2 elements through every wall.** Every face's measured wall gets elements of at most half its thickness, held through the wall. A wall is measured by rays from the face along its inward normal to where they leave the material: a face of another body, a surface closer than 1/100,000 of the part (or twice the CAD face's own tolerance), a face met at a graze, and a face meeting the ray's own at an acute edge (a taper, whose thickness runs to nothing at that edge) are not the far side of a wall, and a face LYING ON the ray's own (26 Oct: two faces of one body that share no edge and are read under that floor somewhere lie on each other - a self-overlapping solid, a zero-thickness membrane on a wall - so every reading of that pair closer than the two faces' own tessellation error, each triangulation's measured deflection added, is the same coincidence and is read through; job bf863215's tube read 0.0055 mm "walls" that way on its 1.2 mm wall, 138M elements) are not the far side of a wall; a face's wall is the thinnest reading at least 3 of its rays agree on within 25%, and a face its rays do not agree on has no wall of its own (`cad/fea_features.wall_reach`). **A wall thin only in places is refined only there** (22 Oct): when a face's thinnest agreed reading is under half its median reading, the readings under half the median are thin spots, grouped where they lie within 2 sample spacings of each other. The rest of the face keeps the wall its other readings agree on. Each spot gets its own zone: the wall rule held off the face, inside a ball round its readings plus one sample spacing (`cad/fea_features.thin_spots`; a sliver between a counterbore and a bore no longer sets the whole bore's size). **A taper is read on the CAD's own edges too** (27 Oct): two faces sharing a CAD edge whose outward normals there turn by more than 92 degrees are a taper whatever their triangles (`cad/fea_measure._brep_tapers`); a whole assembly's coarser tessellation left a cryostat cylinder and the shallow cone it runs into unwelded, read as a 0.0068 mm "wall" - 1.3 billion elements. |
| PLAN-fea-4 | in force | **Hot spots: 6 elements per quarter-turn** of every hole, fillet and notch or groove (quadratic tetrahedra: their curved sides follow the arc), and 3 through the wall beside it, held out to half a radius off the feature, then growing at 1.3. Was 10 per quarter-turn held out to one radius, which made small assemblies 1.7 to 2.8M elements; the textbook Kt cases stay within tolerance at 6 (lab, 24 Oct). **A bore is not a hole** (27 Oct): a concave cylinder sharing its axis with a wider convex cylinder of the same part, round at least half way, over at least half the bore's length, is the inside of a tube, sleeve, ring or hollow shaft - its main wall, sized by PLAN-fea-3 - and gets no hot spot; it is named (`cad/fea_features.is_bore`). A tube's 533 mm bore sized as a hole (3 elements through its 1.2 mm wall, its whole length) was 2.6M of job bf863215's 3.9M elements. |
| PLAN-fea-5 | in force | **Sharp inside corners are capped** at a quarter of the wall beside them, and refined no further: their stress never settles under refinement, so more elements there buy nothing. A corner whose faces read no wall of their own is capped against the thinnest wall of its own part in an assembly (PLAN-fea-17), never another part's; a single part's, or a part with no wall read, against the thinnest wall measured. |
| PLAN-fea-6 | in force | **Gentle growth:** element sizes grow by at most 1.3 from one element to the next away from every refined zone. |
| PLAN-fea-7 | in force | **Every curved face keeps its shape:** at least 4 elements per quarter-turn (about 16 round a full circle; quadratic elements) of every round face that is not a hot spot - a cylinder or torus by its CAD radius, and any other curved face (a swept wire, a spring's coil, a free-form blend) by its own tightest bend, read from its principal curvatures sampled over the face (`cad/fea_measure.face_radius`). A bend gentler than a quarter of the part's diagonal is left to the base size. A round bar or wire so gets at least 3 elements across its diameter (a coil spring's wire came out a 4- to 6-sided ribbon, 22 Oct). |
| PLAN-fea-8 | in force | **Under the element limit, never a stop before meshing.** The element estimate is checked before meshing against the limit: 8,000,000 elements, or fewer when the mesher could not build that many inside its time guard (PLAN-fea-13). Over it, the finest zones are made coarser - a floor size doubled from the finest until the estimate fits - but never past what keeps elements valid: at least 1 element through every wall and 3 per quarter-turn of every round. What that leaves short of the rules is named (`resolution_short`) as a note on the delivery. When even those minimums are over the limit, the part is meshed at them anyway and told so (Areen, 21 Oct); the search stops as soon as a coarser floor changes no zone. An estimate the size field stopped counting short is never zero: the volume it had not resolved is counted at the size its zones ask for (fea0221 read 0 elements, and its time guard fell to the floor). **A count is finished before it decides** (27 Oct): a count of the zones that ran out of cubes while still under the limit is counted again with four times the cubes, up to 12M, and counted to 1.5 times the limit; a count still short there is a floor, and under the limit it fits (a plan short of its machine steps up when it runs, RUN-3) - before, an unfinished count never said a plan fits, so plans that fitted were coarsened (18 of the corpus; job bf863215's bolt fillets at 3 elements per quarter-turn instead of 6). **Over the limit, the low-stress bulk is coarsened first**, kind by kind and each only as far as it must: rounds (their shape only), capped corners, walls and the parts' own sizes, and only then holes, fillets and notches; kinds coarsened to their minimums before a later kind fitted are given back as far as the plan still fits. The plan records each kind's floor and the kinds kept at their rules' sizes. |
| PLAN-fea-16 | in force | **The plan is sized by the accuracy rules, not by a machine.** The element limit is what the LARGEST machine allowed holds (RUN-2: an m1-ultramem-40, 961 GB, 90% usable), by the measured model peak = 450 MB + 5,100 bytes per element with 1.25 times to spare (lab VMs, 22 Oct) - about 145M elements (`engines/fea_driver.element_limit`). The Cloud Run job's memory and the old 8M cap no longer coarsen a plan (Areen, 24 Oct): a plan they cannot hold runs on a bigger machine (RUN-1). Only past the largest machine is the plan coarsened (PLAN-fea-8), never past what keeps elements valid; when even the least valid mesh is over it, the part is meshed anyway with a plain note. The model, the machine and the limit are in the why record. |
| PLAN-fea-14 | in force | **The base size is the coarsest the part allows** - its diagonal over 10 - and every rule refines below it where it asks to (walls, hot spots, corner caps, rounds, growth). That is the mesh the rules recommend; there is no detail level. |
| PLAN-fea-9 | retired | **One part only** (version 1): a file of several bodies stopped before meshing. Retired 23 Oct by PLAN-fea-17: an assembly is meshed. |
| PLAN-fea-17 | in force | **An assembly is meshed, its parts joined as the user said** (`cad/fea_assembly.py`, `engines/fea_assembly_deck.py`). Each solid body is a part, Part_k in OpenCASCADE's order, named from the CAD product (else by its number); several files uploaded together are joined into one such file first (`cad/ingest/assembly_files.py`), each part where its file puts it. Every face is Part_k_Face_j (the j-th face of part k). OpenCASCADE's general fuse finds where parts TOUCH (a face both share: a contact candidate) and where they PASS INTO each other (a solid both share: interference); the stage marks both and asks one question, how the parts are connected - the answer every pair takes unless it is set on its own (PLAN-fea-19). **Bonded** (welded or glued, the default): the fuse itself is meshed, so the parts share their nodes where they touch (one conformal mesh), and a shared piece of interference is one piece of material kept by the smaller body (PLAN-fea-20), said in a note; should the fuse fail, the parts are meshed apart and tied (*TIE / BCTABLE IGLUE / CONTA174 bonded), never a stop. **Contact** (they can slide or separate): each part is meshed on its own and every touching or overlapping pair is a named contact pair, the smaller surface the slave (*SURFACE + *CONTACT PAIR, hard and frictionless as a default to change; Nastran BCPROP + BCBODY + BCTABLE + BCPARA with the surfaces as BSURFS; Ansys TARGE170 / CONTA174). Each part is its own element set (and PSOLID / material number), sized by its own rules - its base a tenth of the part (PLAN-fea-14 per part), held all through the part, not only on its faces - and the element limit (PLAN-fea-8) covers the whole assembly. A part touching no other is meshed and said; a part wholly inside another, which has no surface to pair with, is said, never dropped quietly. A bonded mesh killed for memory is not tried again tied (LAD-fea-7). **Parts that meet tangentially are tied from the start** (27 Oct): where, in the fuse, outer faces of two parts meet at an edge with outward normals within 5 degrees of opposite - a round of one running onto the other's face, a crack of no angle - no mesher can fill the fused parts (job bf863215: each bolt's head fillet onto its washer, "PLC Error: A segment and a facet intersect"), so the assembly is meshed apart and tied, said in a note (`cad/fea_assembly.tangent_meets`). **Every zone has its own id** (rulebook 43): a face zone of an assembly is named with its part and face, W2.9 for Part_2_Face_9 (a single part keeps W9), so a lever, a check row or an AI choice that names a zone names one part's zone - before, every part's Face_9 was "W9" (44 of 46 assembly plans in the FEA hunt, 27 Oct). |
| PLAN-fea-10 | in force | **A cusp is set aside, and named.** Where two CAD edges of one face leave a vertex within 5 degrees of each other (a bore or boss just touching a straight face; a nut's chamfer meeting its flats), the material runs to nothing and no element there can be well shaped at any size. The plan finds every cusp before meshing (`cad/fea_measure.cad_cusps`); the elements touching one get straight sides (always valid: a positive Jacobian), are set aside from the quality floor, and the mesh is delivered with a concern naming each place: the material runs to nothing here, so stress at this point is not meaningful; round it off in CAD for a clean mesh. Every other element must meet the floor (Areen's decision, 21 Oct). |

The plan finds them before meshing (`cad/fea_measure.cad_micro`); the elements on them get straight sides (always valid), are set aside from the quality floor, and the delivery names each detail and says that stress right at it is not resolved - on a gear, the contact stress at the tooth tips. | PLAN-fea-18 | in force | **Where parts meet is measured on their surfaces, and parts across a small gap are joined** (`cad/fea_joins.py`, `cad/fea_assembly.joined_interfaces`). Every pair of parts whose surfaces come near is read pair by pair on the surfaces themselves, never by asking a solid what is inside it (a part whose surface crosses itself answers that wrongly - 26 Oct: a tube whose hole cuts left a skin of no thickness made the fuse put a bracket "100% inside" a tube it does not reach and miss the same joints on the mirrored side): faces whose outward normals face each other (within 45 degrees of opposite) TOUCH within the fuse's own fuzzy distance, or face each other across a SMALL GAP of up to 0.5 mm, or 2% of the smaller part's box diagonal when that is less - the bonded-contact tolerance a solver user sets for a weld or a thread the CAD does not draw (a boss sleeved into a clearance hole, a bolt in its bore); a wider gap (a bolt in a clearance hole) stays a clearance. Parts whose surfaces come within the gap limit only along a LINE, an EDGE or at a POINT (no faces facing each other over the least joint area: a tube on a plate, a plate's edge on a frame, a ring in a countersink, corners a hair apart; the industrial hunt, 27 Oct) are joined there too, the faces that come near tied with the gap limit as the solver's reach; faces that face each other across a band that closes to nothing touch along a line, and are said so. A joint needs (1% of the smaller part)^2 of facing area. A face another part passes through that also crosses, or lies on, another face of its own part is a SKIN: its crossing joins nothing, and its faces are named for the sizing. The fuse's interfaces are checked against the surfaces (the JOIN CHECK): a pair it joins whose surfaces are apart or meet only on skins, or a part it puts wholly inside another whose box it is not inside, sets the fuse aside - the measured joints are used, and a bonded assembly is meshed apart and tied there; otherwise the fuse's interfaces stand exactly as before, and each small-gap pair, and each touch the fuse missed (two coincident faces it did not merge, parts meeting along a line - the public assembly corpus has them, 27 Oct), is added after them and tied. The stage proposes each gap joint in words with one switch, on by default ("Join parts across small gaps"); bonded, a gap joint is tied, contact makes it a contact pair. Every gap pair carries its measured gap and its REACH (the widest gap on its faces and a quarter more). EVERY TIE IS SETTLED before it is written, the same in every solver (`engines/fea_assembly_deck.settle_ties`; the deep test of #334, 28 Oct: a fused joint also tied stopped CalculiX with "zero coefficient on the dependent side", and ties that moved their nodes gave 8,804 "nonpositive jacobian"): its TOLERANCE is the gap pair's reach, or 5% of the master's typical element edge where the parts touch - and, where they pass into each other (a press fit), the slave's nodes inside the master part down to one master element edge; its SLAVE is the side with more nodes within that tolerance of the other - the finer mesh there - and the smaller surface when they are even, unless that side is another tie's master (a master is never a slave too); a slave node is tied only when it is not the master's own node (where the parts are one mesh they are joined already), lies within the tolerance of the master surface, is not held by a nearer tie (a node follows one master) and lies on no tie's master surface (no chains of ties: one comes back round where the parts are also fused, and CalculiX loops on "zero coefficient" without end); a tie whose slave nodes are all the master's own is a bonded joint, its faces still named. Each solver gets the same pair, slave and tolerance and ties the nodes where they stand: *TIE on a node surface of exactly the nodes tied, POSITION TOLERANCE, ADJUST=NO; Nastran BCTABLE ERROR; Ansys CONTA174 pinball (real constant 6) with KEYOPT(9) = 1, its contact elements only on the slave faces that hold a tied node. `assembly.json` names the gap faces and the skins (`joins.gap_faces`, `joins.skin_faces`), for the sizing to read. The stage reads the joints within 150 s, the run's staging within 600 s; a measurement cut short keeps the fuse's answer, said. |
| PLAN-fea-19 | in force | **Each pair of parts is joined as its own choice says** (`cad/fea_pairs.py`, `cad/fea_assembly.stage`, `engines/fea_assembly_deck.py`). ## LAD-fea: the FEA driver's fixed lever ladder

One attempt runs at most 3 passes. After a pass, the first trigger that holds pulls its lever, each
lever at most once. The passes do not use up the run's attempts.

| ID | Status | Rule |
|---|---|---|
| LAD-fea-1 | in force | **An invalid mesh** (a degenerate or inverted element): the next pass grows sizes more gently (1.2) and optimises three times instead of once. Elements under the quality note floor are a note, not a trigger. |
| LAD-fea-2 | in force | **No mesh came back** (the fill failed): the next pass uses gmsh's other 3D algorithm (HXT instead of Delaunay). |
| LAD-fea-3 | in force | **A plan rule fell short on the mesh** (through a wall, or round a hot spot): the zones that fell short are made 20% finer - never on a plan coarsened to fit the limit, which is short there by choice and says so. |

(`contracts/mesh_machine.py`, `mesh_machine.json`) and the mesh executor runs it there
(`adapters/mesh_execution/cloud_run_client.py`, `gce_vm.py`).

| ID | Status | Rule |
|---|---|---|
| RUN-1 | in force | **Decided before meshing, from the memory model.** The mesher's peak (the engine's measured model, with its margin) plus the workspace's files (Cloud Run keeps them in memory: about 2,300 bytes an FEA element) is held against the Cloud Run mesh job (32 GiB, 90% usable). It fits: Cloud Run. ## The FEA builder's AI decisions (AI-fea-n): AI governs, rules guarantee

The builder model (the builder route) is shown the part as measured and the user's own words, and
answers ONE `fea_decision` tool call against a strict schema: no mesher command, no size. The rules
below turn each choice into exact sizes. The round goes through the AI decision cache, so the same
part with the same words gets the same decision and the same mesh. `FEA_AI=off` gives the rules'
own plan.

| ID | Status | Rule |
|---|---|---|
| AI-fea-1 | in force | **Refine** (the stress there matters to this user or this analysis): a hole, fillet or notch gets 10 elements per quarter-turn and 4 through the wall beside it; a wall 3 through it; a round 6 per quarter-turn (as a hot spot). Never finer than half the size the zone's own rule asks for; a sharp corner is never refined past its cap (its stress never settles). |
| AI-fea-2 | in force | **Coarser** (it does not matter for this analysis): a hole, fillet or notch keeps only its shape - 4 elements per quarter-turn and 2 through the wall, as any round (PLAN-fea-7); a sharp inside corner is capped at half its wall instead of a quarter. Walls and rounds are at their minimum already and stay. |
| AI-fea-3 | in force | **Small features.** Set aside: a hole, fillet or notch of radius at most 2% of the part's diagonal is meshed as coarser (AI-fea-2); a wall or anything larger is never set aside. Keep: a micro detail (PLAN-fea-12) at least a fiftieth of the base size gets a zone of its own size, so the mesh follows it; a smaller one stays set aside. |
| AI-fea-4 | in force | **An element count the user named is read by the AI** - only one they stated, in any words they wrote it (`1.2mil`, `half a million`, `700k-1.5M`, a count of nodes converted at about 1.5 nodes per 10-node element) - as `target_elements`, with `target_min` / `target_max` for a range or alone for a ceiling or a floor. The prompt names what is NOT a count: lengths and sizes (`2.5 m`, `3 mm fillets`, `2 mm elements`), bolt and thread sizes (`M8`), loads, pressures and stresses, densities per quarter-turn or through a wall. The rules check the answer: whole numbers between 1,000 and 10 billion, a range's minimum not over its maximum, a target outside its own range replaced by the range's middle; anything else is refused with a note and the rest of the decision stands. The count no longer lowers the element limit: the whole plan is scaled to it, both ways (PLAN-fea-27). There is no reading of the notes outside the AI: with the AI down, the decision saved for the same question answers (AI-fea-6); with none, the plan is the rules' own and the words and the result say plainly that an element count in the notes was not applied this run because the AI step did not answer. (Before 5 Nov the count was `budget_elements`, read the same way when a saved answer replays, and it only ever lowered the limit.) |
| AI-fea-5 | in force | **The minimums hold** after every choice: no choice leaves fewer than 2 elements through a wall, 4 per quarter-turn of a round or hot spot, or a corner coarser than half its wall. Then the plan is held to valid elements, the element, memory and time limits and every gate exactly as any plan is - over the limit, PLAN-fea-8 coarsens it to its validity minimums and names what is short. A zone the AI refined is checked on the mesh against its own finer target, so a refinement the mesh missed is named and pulls LAD-fea-3. The AI's refinements never cost the rules' own zones: when they would take the plan over its limit they are left out first (its other choices stand), and only then does PLAN-fea-8 coarsen. |
| AI-fea-6 | in force | **The AI never fails a run, and its availability never changes the mesh.** Unreachable, busy, slow (240 s, or what the attempt has left after 15 minutes kept for meshing, if less), no tool call, an answer the schema refuses: the decision saved for this same question (the AI decision cache: the same part, the same words, the same owner) is used when there is one; otherwise the rules' own plan. Either way it is said in one line and the why record names which. Off (`FEA_AI=off`): the rules' own plan. Choices on ids the model was not shown are dropped and recorded. |
| AI-fea-7 | in force | **Joints** (an assembly): bonded or contact per touching pair is shown as a suggestion for the user to confirm; it is never applied by itself. |
| AI-fea-8 | in force | **After a failed pass** (no mesh, or an invalid one) the AI may pick one lever from those the ladder allows for that failure (`engines/fea_ladder.lever_options`): the ladder's own first, the other unpulled fill lever, or LAD-fea-6. Any other answer: the ladder's own. |
| AI-fea-9 | in force | **Element sizes per part, read from the notes** (`engines/fea_part_sizes.py` on NOTE-4's shared reading). The phrases that ask for a size on particular parts ("an element size of around 3-4 mm for the frame rail, and 1.5-2 mm for the brackets, bolts and washers") are tied to the parts by the vision model and checked (NOTE-4), and become {part: [min, max]} for PLAN-fea-29. The model never gives a size of its own: it repeats the user's numbers from a quote of their words. No answer and none saved (AI-fea-6), FEA_AI off or no notes: nothing is applied and, with notes, said. Every entry, the mapping and the pictures are kept in the plan (`part_sizes`) and the result (`part_sizes`) for the console. |

The AI decisions are `engines/fea_ai.py`.

## MESH: a good file is never blocked by our own broken-CAD checks

Areen, 24 Oct: mesh first. A pre-mesh check that the CAD may be broken warns; only a mesh that then
fails at the flagged spot tells the user the part needs CAD repair. Detect only, never heal
(`cad/suspect_defects.py`, `application/fea_check.py`, `engines/fea_driver.py`).

| ID | Status | Rule |
|---|---|---|
| MESH-1 | in force | **Warn, then mesh.** Wherever a closed solid can be read (a CAD file with a solid body, or a triangle file whose surface closes), a face crossing another of its body, a paper-thin fold, and an open or invalid patch the clean check finds are WARNINGS on the stage, with the faces named - never a stop. The run meshes; a valid mesh is delivered with a note naming the spot. The only stops before meshing are a file no closed solid can be read from (a surface, or nothing) and an unreadable file. A defect is CONFIRMED only when two independent measures agree (the fold's gap test or the crossing search, and OpenCASCADE's Boolean self-interference check on that solid alone naming the same faces); anything less is a note. |
| MESH-2 | in force | **Needs CAD repair only where the mesh failed.** When every pass fails and the faces the mesher failed on (gmsh's own error, or the invalid elements) are faces a check flagged, the user is told the part needs CAD repair, with those faces named; the run is not taken again. A failure anywhere else is the ordinary FEA outcome. |
| MESH-3 | in force | **Zero false stops, gated.** Every broken-CAD check runs over the known-good files (`devtools/quality/broken_cad_gate.py`): CI holds the fixture set to zero stops on every change, and any change to a check runs the whole corpus (the clean CFD corpus's gate tier, the FEA corpus dev and holdout - presence and verdict only - Areen's files and the assembly corpus A set) on a lab VM, which must show zero stops. |
| MESH-4 | in force | **Meshed at the CAD's own scale when metres fail.** The staged solid is in metres, so OpenCASCADE's fixed tolerances (1e-7 of a model unit) are a tenth of a micron: a CAD edge of a few nanometres where one feature grazes another (libredrive_pulley_housing: a 1.8 mm half-hole touching a 28 mm bore, edges of 24 nm, 56 um and 24 nm) falls inside them, and gmsh stops ("Impossible to mesh periodic surface", "overlapping facets", a volume left empty). When the metre build of a CAD solid fails in the surface stage or the fill, the same file is read again at millimetre scale (the same entities and tags, every length of the plan or spec times 1000), meshed and curved there - every CAD curve shorter than PLAN-fea-12's micro length (a thousandth of the part's diagonal) as one segment, since gmsh's two segments on a nanometre curve put a node on its chord and fold the face beside it - and the nodes are scaled back to metres; quality.json says `fea_mesh_scale: mm` and how many curves were one segment. Only after a failure: a solid that meshes in metres meshes exactly as before. FEA adapter and the CFD gmsh path's CAD solids alike; a failure at both scales names its surfaces for LAD-fea-6 and MESH-2, the 2D stage's own error included. |
| MESH-5 | in force | **A face's repeated triangles are dropped before the fill.** gmsh's periodic mesher can lay the same three nodes down twice where a seam runs into a pole (nakuja_rocket's nose cone, Part_2_Face_5: an interior node placed just across the seam), and the fill refuses the boundary ("Found two duplicated facets", "overlapping facets on surface 5 surface 5") whatever the 2D algorithm or the scale. After the surface stage, each face keeps one copy of any triangle it repeats - a copy adds no surface - and none when the pair is a flap (an edge of it bounds no other triangle of the part's surface: a fold out and back over nothing, which would leave a triangle no element has as a face), and the fill goes on; a curved element the seam bends wrong is straightened by PLAN-fea-11. A face with no repeat (every mesh the fill accepts) is untouched. quality.json names the faces and copies. The CFD gmsh path does the same in its MESH-4 retry. |
| MESH-6 | in force | **Each CAD entity consults only the size fields that can size it.** gmsh reads the background size at every point it places, and the smallest-of field evaluates every field there - each Distance field a nearest-point search. A large assembly's plan makes hundreds: ox_mc_lid (253 parts, 545 zone groups) made 2,291 fields, 753 of them Distance fields over 22.9M sample points, and gmsh spent 2.0 s on each of its 18,229 curves - about 10 hours before the first surface (lab, 26 Oct). Before meshing, every field's lowest and highest possible value over each CAD entity is read from boxes (the entity's, and its sources' or balls', both widened by 5% of their own size plus 1e-4 of the model's): a Threshold is at least its value at the least distance between the boxes and at most its value at the farthest (each source holds a sample point), a thin spot's Max at least the larger of that and its balls'. The entity's ceiling is the smallest of the base size, a part's own base where its Constant field holds (its volumes and what bounds them) and every field's highest there. A field whose lowest is above the ceiling (by 1e-6 of it) can never be the smallest on that entity, so it is wrapped in a Restrict field that skips it there. Every size gmsh reads is the same number as before, to the bit, so every mesh is the same mesh - sooner. ox_mc_lid's curves then consulted 11 fields each (the median) instead of 1,006. FEA plans only; the CFD gmsh path has one field. |
| MESH-7 | in force | **Parts meshed apart are each filled with only their own surface mesh in the model.** gmsh's Delaunay reads the surface mesh of the whole model for every volume it fills - each boundary node's size from every face's triangles, and a search structure over every face's triangles to sort the tetrahedra - so filling a tied or contact assembly part by part costs the parts times the whole surface mesh: ox_mc_lid's 253 parts beside 4.9M surface elements spent about 30 s a part before a single tetrahedron (lab, 26 Oct). While one volume is filled every other surface's triangles are set aside; after the last fill each is put back as the fill left it (same elements, tags, order and orientation) and the nodes and elements are numbered as gmsh numbers them after a fill. A part's boundary nodes are its own, so each fill reads exactly what it read before: the same mesh, to the byte (6 small volumes beside 1.4M surface triangles: 13.9 s -> 2.0 s). Bonded parts fused into one boundary are filled in one call, as before. |
| MESH-8 | in force | **A skin of no thickness is left out of the mesh** (26 Oct, `cad/zero_skins.py`). A face lying on another face of the same solid, the other side out, with no material between them - a hole or pocket cut exactly to a wall, its floor left on top of that uncut wall - is a skin: every sample point of it lies on the other face's surface and inside its boundary, with opposite normals, and the two share no edge. No mesher can fill a solid that crosses itself so (job bf863215's tube: gmsh's "PLC Error: A segment and a facet intersect", alone and fused, at every size). Each part of an assembly is meshed with its skins left out and their outlines opened through the face they lay on, so the opening goes through; every other face keeps its CAD name, the decision names the skins, and the delivery says so. Nothing with material changes: the opened part is kept only when it is a valid closed solid of the original's volume, else the part is meshed as drawn and the ladder goes on (the fTetWild rung, LAD-fea-9, fills a part that crosses itself). The CAD file is never altered. **Every skin is accounted for** (27 Oct): the sidecar records each skin face with the face it lies on ("Part_7_Face_1 lies on Part_7_Face_5: zero thickness, no volume"), and every solver file's notes and the deck record list them. The measured face check (`engines/fea_review.face_accounting`, written to quality.json as `fea_faces`) counts a skin left out - like a tiny face MESH-9 merged into its neighbour - as accounted for, never as a missing named face; the reviewer's facts and the result screen say where each went. A review finding on the face count that this measurement settles is recorded as passed, and an FEA mesh the measurements call valid passes its review: its points stand as concerns (VER-4, `final_result.limits_decide_for`). Job fb44fed7, a valid 11-part mesh, read "FAIL" over 142 named faces against 146 - its 4 skins. |

At mesh time, on the model only (the CAD file is never changed), a face whose width (twice its area over its perimeter) is under 0.005 of the smallest element size the plan can put on it or its neighbours (the FEA plan's zones read the way MESH-6 bounds them; on the CFD gmsh path the clamp size, its curvature sizing and the passage field) is meshed as one gmsh compound surface with one neighbour: a smooth one first (the faces' normals within 30 degrees, the feature angle the snappy path uses), the one it shares the most boundary with; with none, as Ansys's mesh defeaturing drops a feature at or under its Defeature Size whatever the angle, the sliver COLLAPSES onto its edge with the neighbour across the crease it shares most with (the corner moves by less than the sliver's width; quality.json says collapsed, and the crease). Never into another part (both faces bound the same solids), never into or out of a face of a joint between parts (bonded, tied or contact), never a face a stress hot spot names (PLAN-fea-4: a hole, fillet or notch; a corner PLAN-fea-5 caps is not one, its stress never settles and a sliver drawn there is the corner), and on the CFD path a face that is its named group's only face never goes into another group (a neighbour in its own group comes first). | MESH-24 | in force | **A CAD edge far shorter, or a face far narrower, than the elements beside it gets elements of its own size there** (2 Nov, `engines/gmsh/fea_short.py`). At mesh time (FEA plans, not the fTetWild rung), every CAD edge shorter than 0.1 of the smallest element the plan can put on the faces it bounds (read off the plan's zones as MESH-6 bounds them), and every face narrower than that (twice its area over its perimeter, held against itself and its neighbours), gets a gmsh Distance field on itself and a Threshold: 1.5 times its length (width) within that length (width) of it, then growing at the plan's rate to the base size, as every zone grows - as Ansys and Abaqus resolve such an edge with a local edge sizing. Edges and faces MESH-9 meshes through (compounds) are left to it; a curve of no length (a pole, under a millionth of the base size) or one bounding a single face (a seam) is never sized. A narrow face and the short edges that bound it are one unit, sized together or left together (an end edge sized without its strip grades the strip's slivers into worse ones). THE BUDGET: the elements the fields add are estimated at the plan's density (per_h3) - a graded ball round an edge, a graded tube along a face - and may come to 25% of the plan's estimate (at least 25,000); past it the units smallest against their neighbours' size are sized first and the rest left as drawn. NEVER WORSE: when a sized mesh still misses an element-quality limit (the floor, scaled Jacobian, Jacobian ratio, aspect or dihedral rows of VER-2), or was not built, the same pass is meshed again with every short edge as drawn and the better of the two is kept - fewer of those rows missed, then the better worst scaled Jacobian (FEA corpus, 3 Nov: 5 of 21 sized parts kept as drawn; that costs those parts a second mesh). quality.json `fea_short_edges` counts the edges and faces sized, the shortest and narrowest, how many the budget left, and `kept: as drawn` with why when the as-drawn mesh won. A part with nothing that short has no new field: the same mesh, to the byte. |

## NOTE: the user's own notes

Areen, 26 Oct: customers often know things that help the mesh (an NDA customer's STEP came with a
spec sheet). The intake asks once, keeps their words exactly as typed, and every AI step on every
route reads them as guidance (`contracts/user_notes.py`). They are not acceptance criteria.

| ID | Status | Rule |
|---|---|---|
| NOTE-1 | in force | **Asked once, kept word for word.** Before the first summary the application asks one optional question ("Anything specific about this simulation we should know? ... Say 'no' to skip."), unless the user already said something specific. It is never asked again and never holds a submission. The user's answer, every message the intake quotes as saying something specific, and the console's notes box are stored verbatim on the session (`user_notes`), never as a model's rewrite; the summary (request_txt) stays the intake's own. |
| NOTE-2 | in force | **Every route's AI steps read them, as guidance.** Every attempt's workspace gets `user_notes.txt`; the model-led builder, the snappy planner and the FEA judgement calls are shown them and may use them only through the settings they already control, inside those settings' limits; the intake sets a note that fits a declared field (detail level, an engine parameter, a named boundary, far-field margins) there. A route with no AI step in its build (snapgrid's ECXML driver) gets them through the intake. `tests/unit/hygiene/test_user_notes_every_route.py` fails when a route or an engine has no reader. |
| NOTE-3 | in force | **A note is never a check.** The reviewer reads them as context, outside the text a finding may quote to ask for a rebuild, and never fails a mesh over one. What a note asks that cannot be done (removing holes from the CAD, say) is left and the run carries on. A step may leave one plain line on what it did with them, shown on the result as "From your notes: ...", best effort and never parsed or checked. |
| NOTE-4 | in force | **The notes' phrases about particular parts are tied to the parts by LOOKING at them** (`cad/part_words.py`, `render/part_pictures.py`; any route). CAD part names are often missing or meaningless, so the vision model (the reviewer route, the model the geometry check asks; never DeepSeek) is shown a table of the parts as measured - CAD name, box (longest first), volume, how full its box is, walls, bore and shaft diameters, how many alike, what each touches - and pictures: the whole model from three sides, every part its own colour with its number on it, and each part alone. It answers per phrase: the part ids, what is asked (a size, finer, coarser, a name), the user's own numbers and unit, the quote, why, and how sure. The rules check it: the quote is found word for word in the notes, a size's numbers are in the quote, min <= max and both positive, mm / cm / m / in converted to mm, every id a part, the size no finer than 1/2000 of the part and no coarser than the part itself, sure enough (0.6: "unsure" applies nothing), no part given two sizes. What fails applies nothing for that phrase, with a plain note; it never fails a run. The answer is kept and replayed by the decision cache like every AI step (AI-fea-6). Measured (5 Nov, lab, gpt-5.6-terra): a customer's 9-part bonded assembly and the note above - mapped right with the CAD names and again with every name blanked (by shape alone: the long hollow beam, the hex-headed cylinders, the flat rings, the short tubes, the plates with holes). |
| NOTE-5 | in force | **The user sees which parts their notes mean BEFORE they approve, and fixes it in one click** (`application/part_matches.py`). The geometry check keeps a model of two or more parts as it measured it - NOTE-4's facts table and pictures, on the labelled surface that exists only there - beside the check. When the request card is drawn, the notes and the parts are hashed; a reading of that key is shown, else one is queued on the geometry worker (the model can take 3 minutes; never on a request) and the card says "Reading your notes…" until it lands. The card shows one picture - each row's parts in the row's colour, the rest grey; hovering or opening a row shows only its parts; a part's number only where that part is SEEN (read off an id picture, no two numbers touching; the model's own pictures too); a second side offered only when the first hides a part - and a row per phrase - the user's words, the parts, the size ("frame rail · part 9 · 3–4 mm") - and a line per phrase the model was not sure of ("Couldn't tell which part is …"); nothing when the notes name no part, or when the AI step did not answer (the run then reads the notes itself). A row opens the part list; a click on a part - in the list or on the picture - keeps the pick at once, checked by NOTE-4's rules as the user's own (sure; the quote and the numbers still the notes', the size still sane for each part); no part picked puts the phrase back to "which parts?". There is no extra button or confirm step: the normal Approve takes the reading as the user left it, and the route uses it instead of asking again - only for the notes as they stand (a reading of older notes is never used), and only on parts the run has (same id, same name where both have one). |
| NOTE-6 | in force | **Areas inside a part are named and matched like parts** (`cad/part_features.py`). From the FEA measurement's own faces and hot spots: each hole or group of alike holes, each bore, notch, group of alike fillets, boss or shaft group, the thin walls (ribs, flanges: under half the part's typical wall) and the largest flat faces - each face in one area at most, 40 at most. They join NOTE-4's table ("feature": true, a plain name, how many, the part they are in, their size), the pictures draw each its own colour with an F number (the rest of the part grey), and the model ties phrases like "1 mm at the mounting holes, 5 mm elsewhere" to them, checked by the same rules. The checklist before approval (NOTE-5) shows them as rows the same way, clickable to fix. On the flow route only whole parts are matched for now (the staged STL has no CAD faces). |

## AIG: the AI never fails or retries a run

The rules plan comes first. An AI change is used only when it is valid and inside the rules' bounds,
and every AI error falls back to the rules. These rules cover the AI steps outside the FEA builder
(AI-fea-n above) and the verdict (VER-5).

| ID | Status | Rule |
|---|---|---|
| AIG-1 | in force | **The rules build when the AI builder gives no mesh.** On cfMesh, VMTK, gmsh (CFD) and snappy multi-region, an attempt whose builder model was down, busy, slow, raised, or ended its rounds without submitting a mesh is built in the same attempt by the rules plan (`engines/rules_plan.py`): the same tools, validation and gates, the layer count the request names, every size from the engine's own defaults. It is never an infrastructure retry and never a failed run. The why record and the run's notes say so. `BUILDER_AI=off` builds every such attempt by the rules plan. |
| AIG-2 | in force | **The AI plan is never worse than the rules plan.** Before an AI builder plan is used, its planned cells (the engine's own estimate of the case configure_mesh just wrote, at the sizes the mesher really makes) are checked against the one-job cell limit. When the AI plan is over the limit and the rules plan (`engines/rules_plan.py`) is not, the rules plan is configured instead (`engines/plan_guard.py`), the builder's tool result says so in plain words with both numbers, and the why record cites this rule. An estimate that cannot be read, an engine with no rules arguments to compare, or a rules plan that fails or is no better leaves the validated AI plan in force. cfMesh carries an estimate; VMTK fits every strategy to the limit itself, the snappy planner holds max_cells to it and the FEA AI is bounded by AI-fea-5. |
