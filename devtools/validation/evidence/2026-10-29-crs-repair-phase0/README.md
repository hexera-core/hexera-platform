This is host evidence for the measurement harness, not a rollout-capacity claim.

- Planner: off

## OCCT corpus run (2026-11-05)

`occt-repairable.json` measures the 16 OCCT 7.8.0 files that the 2026-10-18 corpus run reported as
`repaired`, three times each. All 16 were taken, so no subset was hand-picked.

| Measure | Min | Median | Max |
|---|---|---|---|
| Wall seconds | 3.38 | 10.34 | 49.23 |
| Child CPU seconds | 1.78 | 3.48 | 12.27 |

- All 48 episodes ended `repaired`, with no timeout, crash, or worker error.
- Maximum child RSS was 338,416 KiB.
- The verifier signature matched across repeats for all 16 files.
- Each file kept one operation and finished with `valid_after` true.
- Credited repairs total 430 (414 `open_shell`, 16 `small_edge`), equal to the prior run's total on
  the same files.

Limits on these numbers:

- **Not a capacity figure.** The sample was chosen because it repaired. The prior run over all 331
  rows also had 115 `refused` and 43 `manual_cleanup` files, which this run did not measure.
- **Determinism is verifier-level.** It compares the fields in `DETERMINISM_FIELDS`, not output file
  bytes or geometry hashes, and covers one host running episodes serially.
- **Wall exceeds CPU by about 3x at the median.** The cause was not investigated. Wall time includes
  supervisor start-up, and other work ran on this host during the measurement.

```bash
export HEXERA_OCCT_CORPUS=~/cadcorpus/occt/opencascade-dataset-7.8.0/step
CAD_REPAIR_ENABLED=true CAD_REPAIR_FILL_PLANAR_HOLES=true \
CAD_REPAIR_MAX_DEVIATION_RATIO=0.001 CAD_REPAIR_MAX_TOLERANCE_MM=0.1 \
.venv/bin/python devtools/validation/crs_repair_phase0.py <the 16 files> --repeats 3 --planner off \
  --out devtools/validation/evidence/2026-10-29-crs-repair-phase0/occt-repairable.json
```

The 16 files are the `repaired` rows of
`devtools/validation/evidence/2026-10-18-catalogue-growth/catalogue-growth-r2.log`. Corpus paths in
the JSON are written relative to `$HEXERA_OCCT_CORPUS`. No corpus files are committed; the harness
now stages each input in a temporary directory, and input copies from earlier runs were removed.

## Runs

Fixture runs, on `f6eebb22`:

`off.json` measures the committed clean fixture
`tests/fixtures/geometry/transition_rect_to_round.step` three times. All three runs returned
`nothing_to_repair`; median wall time was 1.132 s, median child CPU time was 1.056 s, and maximum
child RSS was 309,392 KiB. The verifier signature was deterministic.

`generated-open-shell.json` measures an OCCT-authored missing-face fixture generated by
`tests.cad_fixtures.write_open_shell_step` three times. Median wall time was 1.095 s, median child
CPU time was 0.999 s, and maximum child RSS was 307,504 KiB. All runs safely refused the repair:
sewing left the target and planar filling was disabled. The verifier signature was deterministic.

`generated-open-shell-fill-enabled.json` repeats that input with
`CAD_REPAIR_FILL_PLANAR_HOLES=true`. The fill was consistently declined because its span ratio was
too large. Median wall time was 1.150 s, median child CPU time was 1.070 s, and maximum child RSS
was 307,440 KiB.

`generated-small-edge.json` measures `tests.cad_fixtures.write_small_edge_step` three times. Every
run routed to `manual_cleanup`; median wall time was 1.078 s, median child CPU time was 0.990 s,
and maximum child RSS was 306,928 KiB. The verifier signature was deterministic.
